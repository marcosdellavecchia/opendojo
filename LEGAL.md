# Open Dojo: brief for legal review

This is an engineering summary to help a lawyer review the free-assets mode
before it is published. It is not legal advice and makes no claim of
compliance.

## What would be published

A web page ("Open Dojo", a working name; its domain is still to be decided,
possibly `jk2web.com/open`) where anyone
can play a multiplayer sword-fighting game in the browser, with no download
or purchase. It runs on a separate test game server.

The page distributes three things:

1. **The engine**, `jk2mvmp.wasm`/`.js`: JK2MV, an open source engine for
   *Star Wars Jedi Knight II: Jedi Outcast* multiplayer, compiled for the
   browser, with two small changes (the engine changes (see `git log`)). It is licensed
   under the GNU GPL v2, because it derives from the game's source code,
   which Raven Software released under the GPLv2. Libraries built into it:
   gl4es (MIT), SDL 2 (zlib), zlib, minizip, libpng, libjpeg (IJG), the
   Emscripten runtime (MIT/UIUC), musl libc (MIT) and libc++ (Apache 2.0
   with LLVM exception).
2. **The game code**, three QVM files inside the asset pack: MVSDK, the
   same GPLv2 game code, with a small patch (`patches/mvsdk.patch`) that adds a
   bot command and replaces names from the original game.
3. **The asset pack**, `opendojo.pk3` (2.6 MB): the map, character,
   skeleton and animations, textures, sounds, menus, text and fonts. Every
   file is listed with its origin in `ASSETS.md`. All of it is
   generated by scripts in this repository or written for it, except the
   bitmap fonts, rendered from two SIL Open Font License fonts (Exo 2, Share
   Tech Mono).

**No file from the commercial game is used, fetched or distributed.** The
browser tests record every request the page makes; only the files above
are downloaded.

## What was done to reduce risk

- **Content:** everything players see and hear was made for this project:
  the map, a box-built humanoid with procedural animation, generated
  textures, synthesized sounds, and written text.
- **Names:**
  - The free mode has a neutral name, "Open Dojo".
  - The original game's default character name, which the code used as a
    folder name, is replaced, and so are three font names (one of them a
    film title).
  - The game type names shown on screen are neutral: "Master Duel",
    "Relic FFA", "Capture the Item".
  - All the game's text messages were rewritten in neutral English: no
    Jedi, Sith, lightsaber, the Force, light or dark side, or weapon names.
- **Credit and disclaimer:** the page says the game is free software (GPLv2)
  and not affiliated with or endorsed by any game publisher or film studio.
- **Licenses:** `licenses/` carries the license texts of the engine,
  every library built into it, the game code and the fonts, and points to
  the source code.

## Questions for counsel

1. **The look and sound of the weapon.** Players fight with coloured,
   glowing energy blades that hum. The art and sounds were made from
   scratch, but the design clearly evokes Star Wars lightsabers. Is that a
   trademark, trade dress or sound-mark concern? If so, what changes would
   address it (for example blade shape or colour, a different hum, physical
   swords)?
2. **The domain and brand.** One option is to publish it under
   `jk2web.com/open`, a domain built on the game's abbreviation, next to a
   site that plays the original game with files the player owns. The other
   is a separate domain and brand. Which is advisable?
3. **Gameplay drawn from the original game.** The game code is the
   original's (GPLv2): saber stances and combat, and telekinetic powers
   (push, pull, grip, lightning) that players can still use with keys,
   although the pack shows no effects for them. Our understanding is that
   game mechanics are not protected by copyright and the code is licensed,
   but is there any concern in offering these mechanics in a free game?
4. **Identifiers left in the code.** Internal names players don't see
   remain: cvar names (`g_jediVmerc`, `g_maxHolocronCarry`), server info keys
   (`truejedi`), file paths the code requests (for example
   `gfx/hud/w_icon_lightsaber`), the engine's own name in technical output
   ("JK2MV", "JK2MP" version strings), and animation names. Renaming them
   all would mean larger code changes. Is keeping them acceptable?
5. **A copyright notice in the engine's source.** The engine's MP3 decoder
   is FreeAmp's (GPLv2, Xing Technology and EMusic.com). One header among
   its files carries a "RAD Game Tools" copyright line, inherited from
   Raven's release. The header defines a constant that is never used, and
   the string is not in the built engine. The free pack uses no MP3s, so
   the decoder could also be left out of Open Dojo's build if preferred.
6. **GPL compliance plan.** Is this sufficient?
   - Publish the complete source (this repository at the deployed commit,
     including the engine changes, the patches and the asset generators, plus the
     MVSDK submodule at its commit) at a public URL.
   - Point the page and `licenses/` to it (`node site/build.mjs
     --source <url>`).
   - Keep it available while the site is served.

   The asset generators are the preferred form for modifying the generated
   assets, so they are published as their source.

## Before publishing, in any case

- Publish the source (this repository) and build the site with
  `node site/build.mjs --source <its address>`: without it, the page's
  source link says the source isn't published yet.
- Deploy the separate test game server and relay (see `README.md`).
- Decide on the name and domain (question 2).
